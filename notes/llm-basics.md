# Transformer 的注意力机制到底在算什么

> 本文为 CodeAtlas 项目自写素材。许可证：项目原创。
> 关键词：自注意力、QKV、多头注意力、位置编码、缩放点积

## 一句话版本

注意力机制在算一件事：**对当前这个位置，其他位置各有多重要，然后按重要程度加权求和**。

它不是"理解"，是一个加权平均。但这个加权平均的权重是**学出来的、依赖于内容的**，
所以它能表达"这两个词有关系"这种信息——这是它比固定窗口的卷积强的地方。

## Q、K、V 分别是什么

同一个输入向量，乘三个不同的权重矩阵，得到三组向量：

| 名称 | 含义 | 直觉 |
|---|---|---|
| Query（查询） | 我在找什么 | 当前词的"需求描述" |
| Key（键） | 我能提供什么 | 每个词的"索引标签" |
| Value（值） | 我实际的内容 | 每个词的"实际信息" |

计算过程：用 Query 和每个 Key 做点积得到相似度 → softmax 归一化成权重 →
用权重对所有 Value 加权求和。

**为什么要分成三组而不是直接用原向量**：如果 Query 和 Key 是同一个向量，
相似度矩阵就是对称的（"A 关注 B"等价于"B 关注 A"），但语言里的关注是**有方向的**——
代词"它"需要关注它指代的名词，反过来不成立。三组权重让这种不对称成为可能。

## 为什么点积要除以根号 d

点积的方差随维度线性增长：维度 d 越大，点积结果的绝对值越大。
softmax 对大数值非常敏感——输入差 10，输出就接近 one-hot，
梯度几乎为零，训练会卡住。

除以 √d 是把方差拉回 1 量级，让 softmax 工作在梯度健康的区间。
这不是调参技巧，是数值稳定性的必要条件。

## 多头注意力：为什么要拆成多组

一组注意力只能学到一种"关系模式"。但语言里的关系是多类的：
语法依存、指代、语义相似、情感一致……

多头注意力的做法是：把 d 维拆成 h 组（比如 512 维拆成 8 组 64 维），
每组独立算注意力，最后拼接。**总计算量和单头基本相同**，
但模型可以同时学到 h 种不同的关系模式。

代价是每组维度变低，单个头能表达的信息变少。实践上 8~16 个头是常见选择。

## 位置编码：注意力本身没有顺序感

注意力是加权求和，而加权求和**与顺序无关**——把输入打乱，
输出只是跟着打乱，模型无法区分"猫追狗"和"狗追猫"。

所以必须显式注入位置信息，三种主流做法：

- **正弦位置编码**：用不同频率的 sin/cos 函数生成，固定不学习。
  优点是能外推到训练时没见过的长度，缺点是表达力有限。
- **可学习位置编码**：每个位置一个向量，跟着训练更新。
  优点是灵活，缺点是完全无法外推——超过训练长度就没有对应向量。
- **RoPE（旋转位置编码）**：把位置信息编码成向量的旋转角度，
  通过 Query 和 Key 的相对角度体现相对位置。这是目前主流大模型的选择，
  因为它天然支持相对位置，外推性也更好。

## 残差连接和 LayerNorm

Transformer 的每个子层都是 `x + Sublayer(x)`，然后做 LayerNorm。

残差的作用是给梯度一条直路：几十层堆叠时，没有残差梯度会衰减到消失。
LayerNorm 的作用是稳定每层的输入分布，让深层网络可训练。

顺序上分 Pre-LN 和 Post-LN：原始论文是 Post-LN（先注意力再归一化），
但深层模型训练不稳定；现在主流是 Pre-LN（先归一化再进子层），
训练更稳，代价是表达能力略弱。

## 为什么 Transformer 能并行而 RNN 不能

RNN 的隐藏状态是递推的：算第 t 步必须等第 t-1 步算完，天然串行。
序列长 1000，就要串行 1000 次。

注意力的做法是把所有位置一次性放进矩阵，整个序列的注意力可以一次矩阵乘法算完。
训练时所有位置并行，这是 Transformer 能在长序列上训练的根本原因。

代价是**计算量随序列长度平方增长**（每个位置都要和所有位置算相似度）。
这也是后来各种稀疏注意力、滑动窗口注意力、FlashAttention 的动机——
它们都是在解决这个平方复杂度。

## 一句话总结

注意力 = 内容相关的加权平均；QKV 让关注有方向；缩放点积保数值稳定；
多头让不同关系模式并存；位置编码补回顺序；残差和归一化让深层可训练；
并行是它取代 RNN 的根本原因，平方复杂度是它唯一的硬伤。
