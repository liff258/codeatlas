# 微调、LoRA 与对齐：动模型之前的判断

面试里问微调，往往不是要你背 LoRA 的公式，而是想知道你有没有判断力：这个需求到底该微调还是该用 RAG？LoRA 为什么能work？SFT 和 RLHF 各自解决什么问题？这篇按「决策 → 方法 → 坑」的顺序讲。

## 什么时候该微调，什么时候该用 RAG？

判断标准只有一句：**问题是「模型不知道」，还是「模型知道但不说人话」？**

- 模型不知道（私域知识、时效性数据、内部文档）→ 用 RAG。知识更新只需重建索引，不用重训，而且能给出处。
- 模型知道但输出不符合要求（固定 JSON 结构、特定语气、领域术语习惯、把长回答压成三句话）→ 用微调。
- 两者都要 → 先 RAG 保证事实，再微调保证形式。

反过来说，两个常见误判：

1. **用微调灌知识**。效果通常很差，模型会「记住一点、编造更多」，而且知识一变就得重训。
2. **用 RAG 改风格**。把「请用简洁的风格回答」写进提示词能解决 80%，剩下 20% 才值得微调。

一个务实的顺序：先调提示词 → 再调检索 → 最后才考虑微调。微调是成本最高、迭代最慢的手段。

## LoRA 为什么能用很少的参数达到接近全参微调的效果？

LoRA 的假设是：微调带来的权重变化 ΔW 是低秩的。于是不去直接训练 ΔW（d×d 个参数），而是把它分解成两个小矩阵 B（d×r）和 A（r×d），只训练这两个，r 取 8~64。

参数量从 d² 降到 2dr。以 d=4096、r=8 为例，从 1677 万降到 6.5 万，约 0.4%。

三个工程上的好处：

1. **显存省**：不用存原权重的梯度和优化器状态（Adam 要为每个参数存两份动量），只存 adapter 的。
2. **可以多套并存**：一个基座 + 多个 adapter（不同任务各一套），切换只换几十 MB 的文件。
3. **推理零延迟**：训练完后可以把 BA 乘回去加到 W 上（merge），推理时和原模型完全一样。

为什么「低秩够用」：已有研究表明预训练模型的内在维度远小于参数量，微调主要是在一个低维子空间里移动。r 太小会欠拟合，r 太大收益递减还容易过拟合，实践中 r=8~16 覆盖大多数任务。

## QLoRA 里的 Q 是什么？它解决了什么问题？

Q 是 Quantization（量化）。QLoRA 把**冻结的基座**量化成 4-bit（NF4 格式），LoRA adapter 仍用 bf16 训练。

三个关键设计：

1. **NF4（4-bit NormalFloat）**：假设权重近似正态分布，按分位数做非均匀量化，比均匀 INT4 更贴合分布，精度损失更小。
2. **双重量化**：量化本身会产生量化常数（每组的 scale），这些常数也占显存，再对它们量化一次，平均每个参数省 0.37 bit。
3. **分页优化器**：显存峰值时把优化器状态换到 CPU，避免 OOM。

效果：65B 模型原本需要 780GB 显存做全参微调，QLoRA 在单张 48GB 卡上就能跑。代价是训练速度慢一些（要反量化），推理时可以把 adapter 合并回基座后再量化部署。

## SFT 和 RLHF 分别在解决什么问题？

**SFT（监督微调）**：给「问题 → 标准答案」的配对，教模型「该长什么样」。本质是模仿学习，损失是 token 级的交叉熵。

它解决的是「格式和基本行为」，但解决不了「哪个回答更好」——因为很多场景没有唯一正确答案，只有相对偏好（更详细 vs 更简洁、更谨慎 vs 更直接）。

**RLHF（人类反馈强化学习）**：让人对多个回答排序，训一个奖励模型（reward model）学习人的偏好，再用 PPO 让策略模型去最大化这个奖励，同时用 KL 散度约束它别偏离 SFT 模型太远。

它解决的是「对齐」：有用性、无害性、诚实性。代价是流程复杂（要训 RM、要在线采样、PPO 超参难调），而且奖励模型会被「刷分」（reward hacking）。

## DPO 相比 PPO 简化了什么？为什么它更常用？

DPO（Direct Preference Optimization）的洞察是：带 KL 约束的 RLHF 目标，存在解析解，可以把它改写成一个**分类损失**——直接拿偏好对 (chosen, rejected)，让模型提高 chosen 的似然、降低 rejected 的似然，隐式地优化同一个目标。

于是省掉了两个东西：不用单独训奖励模型，不用在线采样跑 PPO。训练变成一个普通的监督任务，稳定、便宜、单机可跑。

代价与边界：

- 依赖**离线偏好数据**的质量和覆盖度，不能像 PPO 那样在线探索新回答。
- 对数据分布外的场景泛化差，容易出现「 chosen 变长」这类偏置（长度偏好）。
- 大规模、追求极限效果的场景，PPO/GRPO 这类在线方法仍有优势。

实践建议：数据量小、算力有限、要求稳定 → DPO；有大量在线流量、要持续优化 → PPO 系。

## 微调为什么会灾难性遗忘？怎么缓解？

原因是**分布偏移**：微调数据通常又窄又专（比如全是客服对话），梯度会把权重往这个窄分布上拉，原来覆盖的通用能力被覆盖掉。表现是「学会写工单了，但连基本的常识问答都变差」。

五种缓解手段，按性价比排：

1. **混入通用数据（replay）**：微调集里掺 10%~30% 的通用指令数据，是最有效也最便宜的办法。
2. **LoRA 低秩约束**：只动低秩子空间，对原能力的破坏天然比全参微调小。
3. **只调部分层**：通常调靠后的层或注意力投影层，冻结底层。
4. **早停 + 小学习率**：遗忘往往发生在过拟合之后，验证集上通用能力开始掉就停。
5. **正则约束**：对参数偏离初始值加惩罚（类似 L2-SP），或用 KL 约束输出分布。

评估上必须同时看两个指标：目标任务的效果，和一组通用任务（如 MMLU 子集、自有回归集）有没有掉。只看前者，很容易交出「专项很强、整体变傻」的模型。
