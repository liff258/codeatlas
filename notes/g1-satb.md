## 先看 G1 的回收流程

G1 的并发标记周期大致分几个阶段：

1. **初始标记**（Initial Mark）：STW，标记从 GC Roots 直接可达的对象。
2. **根区域扫描**（Root Region Scanning）：扫描 Survivor 区中指向老年代的引用。
3. **并发标记**（Concurrent Marking）：与应用线程并发，遍历整个对象图。
4. **重新标记**（Remark）：STW，处理并发标记期间发生的引用变化。
5. **清理**（Cleanup）：STW，统计各 Region 的存活对象，回收完全空闲的 Region。

问题出在第 3 步。并发标记期间，应用线程还在跑，对象引用在变。
如果处理不当，会出现两种错误：

- **漏标**（漏掉本该存活的对象）→ 对象被错误回收 → 程序崩溃
- **多标**（标记了实际已死对象）→ 只是浪费空间，下次回收会处理，**可容忍**

所以三色标记法只要求「不漏标」，多标是可以接受的。

## 漏标的两个必要条件

用三色标记的语言：

- **黑色**：自己和所有引用都已扫描完
- **灰色**：自己扫描了，但引用还没扫完
- **白色**：还没被扫描到

一个白色对象被漏标，当且仅当**同时满足**两个条件：

1. 一个黑色对象新增了指向它的引用
2. 所有从灰色对象到它的引用都被删除了

只破坏其中一个条件，漏标就不会发生。这引出了两类解法：

- **破坏条件 1**：记录「谁新增了引用」→ **增量更新**（Incremental Update），
  CMS 用的方案，把新增引用的黑色对象重新变灰。
- **破坏条件 2**：记录「谁删除了引用」→ **原始快照**（SATB），G1 用的方案。

## SATB 的核心：保留「标记开始时」的快照

SATB（Snapshot-At-The-Beginning）的思路是：

> 在并发标记开始时，逻辑上给整个对象图拍一张快照。
> 之后无论引用怎么变，都按快照那一刻的引用关系来判断存活。

实现上不需要真的复制一份对象图，只需要在**引用被删除时**，
把被删除的那个引用记下来。这样即使原引用没了，通过记录仍能找到那个对象，
它就不会被漏标。

这就是「写屏障」的作用：在引用赋值的字节码层面插入一段钩子，
当发生 `obj.field = null` 这类删除操作时，把旧的引用值记录下来，
放进 SATB 队列，由并发标记线程异步处理。

伪代码大致是：

```
// 写屏障（简化）
void pre_write_barrier(Object field, Object new_value) {
    Object old_value = read(field);
    if (old_value != null && is_marking()) {
        satb_queue.enqueue(old_value);   // 记下将被覆盖的旧引用
    }
    field = new_value;                    // 真正的赋值
}
```

注意这里记的是 **old_value（旧值）**，不是新值。这一点常被搞混：
增量更新记的是新值（因为要让黑色对象重新变灰），
SATB 记的是旧值（因为要保住快照里的那个引用）。

## 为什么是「前置」写屏障

G1 用的是 pre-write barrier（赋值前拦截），因为需要在覆盖之前拿到旧值。
如果放在赋值之后，旧值已经丢了。

代价是每次引用赋值都要多读一次旧值。这是 G1 相比 CMS 在某些写密集场景下
略微吃亏的原因之一，但换来的是重新标记阶段可以更短——
SATB 只需要处理队列里的记录，不需要重新扫描整个新生代。

## 和「三色标记 + 增量更新」的对比

| 维度 | 增量更新（CMS） | 原始快照（G1） |
|---|---|---|
| 破坏的条件 | 条件 1（新增引用） | 条件 2（删除引用） |
| 写屏障记录 | 新值 | 旧值 |
| 屏障时机 | 赋值后（post） | 赋值前（pre） |
| 重新标记成本 | 需重新扫描根和被修改对象 | 只处理 SATB 队列 |
| 副作用 | 可能产生浮动垃圾较少 | 可能保留更多浮动垃圾 |

「浮动垃圾」是 SATB 的代价：快照里存活、但实际已经死亡的对象，
这一轮不会被回收，要等下一轮。这是**用空间换正确性**——可接受，
因为漏标会导致程序崩溃，浮动垃圾只浪费一点内存。

## 一句话总结

SATB 的本质是「在标记开始时冻结一份逻辑快照，用写屏障记录被删除的引用」。
它选择破坏漏标的第二个条件，代价是产生浮动垃圾，收益是重新标记阶段足够短，
适合 G1 这种要求可预测停顿的场景。
