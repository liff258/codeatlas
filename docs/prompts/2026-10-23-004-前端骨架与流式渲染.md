## 5. 我的修正与判断

这一轮 AI 写出了能跑的代码，但**跑起来之后暴露了五个真问题**，逐个说：

### 问题 1：最后一个事件会被吞掉（单测抓到的）

`sse.ts` 的 `flush()` 只在「字段已经解析进 `cur`」时才能捞回最后一条事件。
但如果服务端写完 `data: {...}` 就直接关连接、没有那个空行结尾，
残留字节还卡在 `buffer` 里，`cur` 是空的，最后一个 `done` 就丢了。

**这是最严重的一类 bug**：界面会永远停在"推理中"。

修复：`flush()` 先把 buffer 里残余的最后一行当完整行处理一遍，再检查 `cur`。
补了一个用例，还补了「flush 调两次不能吐重复事件」。

> 我的判断：这个 bug 值得单独记一笔，因为它证明**解析器必须可测**。
> 如果当时图省事把解析逻辑写在 `fetch` 的循环里，这个 bug 会一直藏到演示当天。

### 问题 2：内容可见性依赖 JS 动画（我自己发现的）

用 headless Chrome 截图验证时发现：三张特性卡片在 DOM 里存在，但屏幕上什么都没有。
查下来是 `framer-motion` 的 `initial={{opacity:0}}` 在无头环境里没有推进到 1。

**关键判断**：这不只是截图问题。任何「入场动画没跑完就白屏」的实现，
在低端机、动画被打断、JS 报错时都会变成空白页。内容可见性不该挂在动画上。

修复：把所有入场动画从 framer-motion 换成 CSS `animate-fade-up`。
CSS 动画走合成器，不受主线程影响，也不会因为一次 JS 异常就永久隐身。
framer-motion 只保留在真正需要弹簧/循环动效的地方（轨道节点的缩放、推理中的呼吸点）。

### 问题 3：图谱区域永远是空白（最隐蔽的一个）

现象：右栏显示「8 节点 / 2 跨域边」，图例也在，但画布什么都没有。

根因是一个 React 经典陷阱：

```tsx
// 错
const ref = useRef(null);
useEffect(() => {
  const el = ref.current;
  if (!el) return;      // ← 空状态下组件提前 return，ref 根本没挂到 DOM
  ...
}, []);                 // ← 空依赖，只跑一次，之后再也不会重跑
```

组件在「图谱还没数据」时渲染的是空状态，`ref` 没有挂到任何元素上；
`useEffect` 在挂载时执行一次，拿到 `null` 直接退出；等数据到了、主分支渲染了，
**没有任何人再来测量尺寸**，`size.w` 永远是 0，`ForceGraph2D` 永远不会挂载。

修复：改用 callback ref。ref 挂载/卸载时都会回调，天然解决了"什么时候该测量"的问题。

> 单独做了 `graph-preview.html` 来隔离验证。这个页面本来只是为了调样式，
> 结果成了定位这个 bug 的关键——预览页首帧就有数据，所以永远正常，
> 一对比就锁定了「空状态 → 有数据」这个状态迁移。

### 问题 4：力导向图的视野适配时机（调了三轮）

`zoomToFit` 调早了会缩成一团，调晚了节点会跑出画布。中间试过：

| 方案 | 结果 |
|---|---|
| 固定 `setTimeout(260ms)` | 仿真还在扩散，适配到的是随机布局 → 缩成中间一个小点 |
| `onEngineStop` 里适配一次 | warmup 之后 alpha 已经很低，引擎"早早停下"，拿到的是散开的初始布局 |
| `warmupTicks=0` + 延时 1600ms | 布局还没收敛完，节点跑出画布底部 |

最终方案：**在最初 2.6 秒里连续适配 4 次**（400 / 1000 / 1800 / 2600ms），
最后一次一定落在布局稳定之后。看起来像"图谱在自动找位置"，观感反而更好。

### 问题 5：轨道上「引用」那盏灯永远不亮（AI 的 mock 有漏洞）

前端轨道有 8 个节点，但 Python 的 `mock_runner` 从来没发过 `citation` 节点的 `step` 事件
——正文里明明有 4 处引用角标。演示时评委会看到"有引用，但引用节点没亮"。

修复：在 `mock_runner` 里补 `citation running` / `citation ok` 两个事件，重新生成 jsonl，
Python 的 14 个测试仍然全过（没有硬编码事件数，这是当初设计对了）。
