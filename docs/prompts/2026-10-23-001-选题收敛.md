## 1. 目标

从「传智杯 Vibe Coding 赛」官方赛道的 10 个推荐选题中，确定一个既能在 26 天内做完、又能对齐评审标准（尤其 25% 过程复现性 + 25% 实用价值）、同时对 Java 后端实习求职有加分的方向。

## 2. 上下文

- 官方赛道页：`https://www.boxuegu.com/matchTrack/detail/?id=10039`
- 个人情况：大三，民办本科（B 组），Java 技术栈，缺项目经验，重度依赖 AI 写代码
- 硬约束：省赛截止 2026-11-18，个人参赛
- 评审权重：过程可复现 25% / 实用价值 25% / 创新与意图控制 20% / 工程质量 15% / 体验 15%

## 3. 我的 Prompt（关键片段）

> 我把赛道页的完整内容和自己的情况一起给了 AI，先让它做一轮「选题 × 评分维度」的交叉分析，而不是直接推荐。
>
> 第二轮我提了三个约束条件让它收敛：
> 1. 我要「前端视觉冲击 + 计算机知识库 Agent，主要是 Agent」
> 2. 我是 Java 背景，但 RAG/Agent 生态在 Python
> 3. 我需要这个作品能同时写进简历

## 4. AI 的关键输出

AI 给出的核心判断：

1. **选题映射**：10 个方向里，方向 2「场景化轻量 RAG 知识库」最匹配，但必须往「多步推理 Agent」做深，否则会退化成 RAG 套壳，在创新性 20% 上拿不到分。
2. **差异化六条**：检索决策权在 Agent、自评-改写闭环、图谱补足跨跳短板、claim 级引用、全链路 trace、**自建 50 题 gold set 做量化评测**。最后一条被特别强调——"有量化评测的 RAG 和没评测的 RAG 是两个物种"。
3. **双服务的三个必做防护**：契约先行、依赖单向、表所有权隔离。缺任一条，Java/Python 会互相阻塞。
4. **技术选型原则**：选「AI 语料最厚」而不是「最新」的版本。据此否掉了 Tailwind 4（AI 容易编造配置）和 Spring Boot 3.3（已过 OSS 支持期，会被扣工程分）。
5. **三个复现杀手**：PG 的 zhparser（官方镜像没有，编译麻烦）、MinerU（模型下载太重）、全图渲染（必卡）。

## 5. 我的修正与判断

| AI 的建议 | 我做了什么 | 为什么 |
|---|---|---|
| 推荐 Python FastAPI 单体，否决双服务 | **没有采纳**，坚持 Java + Python 双服务 | 我需要一个能写进简历的 Spring Boot 项目。AI 说的"双服务调试成本高"是真的，但它没算上"简历价值"这个变量。折中方案是接受它提的三个防护措施（契约先行 / 依赖单向 / 表所有权隔离）来压低风险 |
| 推荐 Postgres + pgvector | **采纳** | 实测本机 Docker 已装（只是没启动），单库比 MySQL + 向量库双库干净 |
| 建议同时申请 DeepSeek 官方 key 和硅基流动 key | **改为只用硅基流动** | 一个 key 覆盖 chat + embedding + rerank，少一个平台、少一次充值。以后要换 DeepSeek 官方只需改 `base_url` 和 `model` 两行 |
| 排期给到 11/17 完成材料 | **采纳，并加了一条硬规则** | 11/14 功能冻结，11/18 只提交不写代码。AI 没提"冻结日"，这是我补的——不设冻结日，单人项目一定会拖到截止前夜 |
| 没提报名缴费这个卡点 | **我补的** | 官方原文写明提交入口需缴费后才可见，且没有外部链接。这是比技术风险更前置的卡点 |

**一个额外发现**：官方 10 个选题的表格本身是错乱的（第 6/7/8/10 项的方向说明明显错位，第 10 项和第 8 项说明完全重复）。这个不影响选题，但说明赛道页维护质量一般，**所有硬性要求都要以"参赛规则"和"作品提交要求"两节的原文为准，不要依赖表格**。
