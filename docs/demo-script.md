# 演示分镜脚本

> 目标：6 分钟内让评委记住一件事——**这个系统能看见纯向量检索看不见的东西**。
> 其余所有内容（评测数据、工程细节）都是为了支撑这一句话。

## 开场前 30 秒（不录进视频）

1. 起服务：数据库 → Python(8000) → Java(8080) → 前端(5173)
2. 浏览器开 `http://localhost:5173`，**新对话**清空
3. 提前想好：主线题**不要**在录屏时第一次问，先跑一遍预热（免费额度首次调用有 6 秒冷启动）
4. 关掉其他标签页、关通知、把字号调到 110%（录屏时字太小看不清）

## 分镜表

### 0:00 – 0:35　开场：先给结论，再给背景

| 项 | 内容 |
|---|---|
| 画面 | 停在空白首页，不要动 |
| 台词 | "现在的 RAG 产品，本质都是把问题变成一个向量，然后找最相似的几段话。这解决了一个问题：**找不到**。但没解决另一个问题：**看不见关系**。" |
| 台词 | "我问『向量检索为什么不能用 B+ 树加速』，一个普通 RAG 会找到讲向量检索的文章，然后照着念。它不会告诉你：这个问题真正的答案在数据库索引那一侧。" |

**为什么这么开场**：评委一天看十几个项目，前 30 秒决定他后面是认真听还是走神。先抛一个他能立刻理解的对比，比先讲技术栈有效。

---

### 0:35 – 1:50　主线：一次跨域提问

| 项 | 内容 |
|---|---|
| 操作 | 输入：`向量检索为什么不能用 B+ 树加速？那 RAG 的召回率该怎么提？` |
| 画面 | 右栏思考面板逐节点点亮 → 答案流式出现 → 右下图谱长出节点 |
| 台词 | （等路由/规划时）"注意右栏：它在先判断意图，再把问题拆成三个子查询，然后才是检索。" |
| 台词 | （检索完）"召回了 12 条证据，来自 3 篇不同文档。" |
| 台词 | （答案出来）"答案里每个 [1][2] 都能点开看原文——**这是硬约束，不是模型自己标的**：编号由代码分配，模型只能引用已存在的编号，越界编号会被标成『无出处』。" |
| 台词 | （图谱出现，**这里要停 3 秒**）"现在看右下角。**这个问题里没有出现『B+ 树』三个字之外的任何数据库术语**，但系统把 B+ 树和向量检索连起来了，而且是橙色虚线——虚线代表**跨域**。" |

**这段是全场的核心。** 语速放慢，让评委看清那条虚线。

---

### 1:50 – 3:00　拆解：那条虚线是怎么来的（防守段）

| 项 | 内容 |
|---|---|
| 画面 | 图谱全屏（点右下角放大），鼠标指着 `B+ 树` 和 `向量检索` |
| 台词 | "评委可能会想：这该不会是模型自己编的吧。**不是。**" |
| 台词 | "实体的学科归属是**全库统计**出来的，不是从这一条证据里推的。`B+ 树` 在库里出现最多的学科是 MySQL——哪怕它这次出现在一篇 AI 域的文章里，它的归属仍然是后端。跨域边由两端 domain 比较得出，**模型输出里根本没有这个字段**。" |
| 台词 | （可选，如果时间够）"这里踩过一个坑：一开始按『这条证据属于哪个域』推，结果 B+ 树被标成 AI 域，跨域边直接消失了——**产品的核心卖点没了**。改成全库统计才修好。" |

**为什么主动讲踩坑**：评委最怕的是"演示效果是调出来的"。主动说一个自己修过的 bug，可信度比堆十个优点高。

### 3:00 – 4:10　第二幕：它会承认自己不知道

| 项 | 内容 |
|---|---|
| 操作 | 新对话，问：`Kubernetes 的 Pod 调度器是怎么做亲和性打分的` |
| 画面 | 覆盖率 0.20 → 改写 → 0.15 → 改写 → 停止 |
| 台词 | "库里没有 Kubernetes 的内容。看它做什么：自评覆盖率 0.20，低于阈值 0.6，触发改写，换个角度再查——还是 0.15，再改一次，两轮用尽。" |
| 台词 | "然后它说：**现有资料不足以完整回答**，只引用了 2 条勉强相关的。" |
| 台词 | "很多 RAG 演示到这一步会硬编一个答案。我觉得**会说我不会**，比编一个像样的答案难得多，也有用得多。" |

**这段的作用**：证明「自评-改写」不是 PPT 上的流程图，是真的会触发、真的会止损。

| 项 | 内容 |

| 台词 | "顺便说，限流也做了处理：429 会重试两次，还不行就降级。免费额度下这是常态，不是异常。" |

### 4:50 – 5:40　工程证据：数字

| 项 | 内容 |
|---|---|
| 画面 | README 的评测表格（或切到 `/api/eval/runs` 的返回） |
| 台词 | "33 道评测题，四种检索模式都跑过。纯 BM25 的 Recall@5 是 78.8%，纯向量也是 78.8%，混合到 90.9%，**加重排到 93.9%**。" |
| 台词 | "有意思的是 AI 域：BM25 的 Hit@1 只有 46%，向量有 62%——因为 AI 素材大量是英文论文，中文提问和英文正文对不上，**词匹配跨不过去，向量能跨过去**。同一个策略在不同语料上的表现是反的。" |
| 台词 | "发现 AI 域语义题全空之后，我补了两篇中文笔记，占语料 0.5%，总体 Hit@1 从 69.7% 涨到 78.8%。**这说明调参数之前该先看素材覆盖度。**" |

**为什么讲这个**：这一段是"你不是只会调 API"的证据。数据能自己解释设计决策，比说"我很努力"有效。

## 30 秒电梯版（用于答辩开场或评委赶时间）

> "我做了个能看见知识跨域关联的 RAG。问『向量检索为什么不能用 B+ 树加速』，它不只是找到讲向量检索的文章，还会把 B+ 树连过来，用橙色虚线标出这是一条跨域关联——而这个问题里根本没提数据库。
> 跨域判定是代码算的，不是模型说的。33 道题评测，混合检索 + 重排的 Recall@5 是 93.9%。"

## 意外情况应对

| 情况 | 现象 | 怎么说 / 怎么做 |
|---|---|---|
| **模型限流（429）** | 思考面板出现黄色"模型限流" | 别慌，说："这就是降级——它重试两次后改用兜底，继续把答案给你。" 如果答案变成原文摘录，补一句"这是生成失败后的抽取式兜底，检索部分仍然是真的。" |
| **模型超时** | 节点黄色，"模型响应超时（10s）" | 同上。**不要**说"网络问题"——说"免费额度下延迟波动大，所以每个节点都设了超时和兜底" |
| **图谱没边** | 图上只有点没线 | 说："这题的实体在库里没有共现，所以没连边——**没有关系就不画关系**，比硬连一条准。" |
| **答案没表格** | 模型这次没输出表格 | 不要重跑。说："格式是模型自己决定的，我只约束了引用必须可溯源。" |
| **首次调用很慢** | 检索阶段 30 秒+ | 提前预热过就不会。真遇到就说："冷启动要加载三个本地模型（BM25 / embedding / rerank），热态是 4 秒左右。" |
| **完全没响应** | 一直转圈 | 检查 Python 8000 是否还活着。**录屏前务必先跑一遍主线** |

## 录制注意

- **不要用 1080×600 的小窗口录**，图谱会被压扁。用 1920×1080。
- 录屏时**鼠标轨迹要慢**，指向图谱那条虚线时停 1 秒再说话。
- 台词不要背，按分镜表的**要点**说，允许口语化——背稿听起来像念稿。
- 答案长度不可控（模型决定），所以**不要边等边说话**，等答案基本出完再讲下一段。
- 如果主线题那次跑出来的答案不好（模型波动），**重跑一次再录**，不要剪——剪出来的效果不连续，评委看得出来。

## 附：评委可能问的 10 个问题

| 问题 | 一句话回答 | 展开位置 |
|---|---|---|
| 跨域边会不会是模型编的？ | 不会，跨域由 domain 比较算出来，模型输出里没这个字段 | 3:00 那段 / `nodes.py::extract_graph` |
| 为什么不直接用 LangGraph？ | 流程是"线性 + 一个重试环"，while 循环更直观，评审能一眼看到循环控制 | `graph.py` 文件头注释 |
| 引用编号怎么保证不串？ | 编号由代码分配并写进 prompt，模型只能引用已存在的；越界编号保留正文但标"无出处" | `CitationInterceptor` |
| 为什么重排只做一次？ | 单次重排 5 秒，4 个子查询各排一次就是 20 秒；合并去重后统一重排，跨查询候选还能互相竞争 | `retrieve()` |
| 混合检索 Hit@1 没提升，为什么还用？ | 提升在召回率（78.8%→90.9%）。RRF 只看排名，会稀释 BM25 的强第一名；重排把 Hit@1 拉回 78.8% | README 评测章节 |
| 幻觉怎么防？ | 三层：引用必须可溯源、自评覆盖率不足就承认、生成失败走抽取式兜底 | `nodes.py` / `graph.py` |
| 并发怎么样？ | 单人演示级别。BM25 索引进程内单例，检索是同步阻塞的，用 `asyncio.to_thread` 包住不挡事件循环 | `retrieve.py::get_retriever` |
| 数据从哪来？ | 143 篇，全部标注了 license 和出处；自写 6 篇原创笔记 | `sources.manifest.yaml` |
| 为什么用 Java + Python 两套？ | Java 管会话/持久化/SSE 转发（企业里常见的分层），Python 管模型和检索（生态在这里） | README 架构图 |
| 下一步做什么？ | 补中文 AI 素材（评测已证明性价比最高）、把全库图谱离线建出来 | 本文件 + README 路线 |
